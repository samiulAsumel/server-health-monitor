ARCHITECTURE

How the system works

A modular, cron-driven pipeline — each module is independently testable and sourced by the central orchestrator at runtime.

Cron Scheduler

Cron fires health_monitor.sh every 5 minutes. Daily report runs at 08:00. Both jobs are installed by install.sh to /etc/cron.d/healthmonitor.

*/5 * * * * /etc/cron.d/ root

Orchestrator

health_monitor.sh sources config.conf then all 5 check modules. Runs checks sequentially, logs every result with timestamp, and dispatches alerts for any threshold breach.

source modules set -euo pipefail trap ERR

Check Modules

Five self-contained modules: CPU (top/proc), RAM (free -m), disk (df -h all mounts), services (systemctl + auto-restart), network (ICMP + DNS). Each returns STATUS|detail.

check_cpu check_ram check_disk check_services check_network

Alert Dispatcher

send_alert.sh supports email (mailx/sendmail) and Slack webhooks (curl). Cooldown files prevent alert storms — same alert type won't fire twice within 30 minutes.

mailx slack webhook cooldown

Daily Report

generate_report.sh parses 24 h of logs, calculates CPU/RAM averages and peaks, checks current disk/service state, and sends a styled HTML email report at 08:00 daily.

HTML email log parser awk stats

Logging

All check results written to /var/log/healthmonitor/monitor.log with format [YYYY-MM-DD HH:MM:SS] [MODULE] [STATUS] detail. Alerts also written to alerts.log. 30-day rotation.

monitor.log alerts.log 30-day retention

Email (mailx/sendmail)
Plain-text alert sent via system mail agent. Works with any SMTP relay — Postfix, sendmail, msmtp. Configure ALERT_EMAIL in config.conf.
ALERT_METHOD="email"
Slack Webhook
JSON payload sent via curl to your Incoming Webhook URL. Zero dependencies beyond curl — already on every Linux server. Configure SLACK_WEBHOOK.
ALERT_METHOD="slack"
Both channels simultaneously
Critical infrastructure alerts should reach you on multiple channels. Set ALERT_METHOD="both" to fire email and Slack on every threshold breach.
ALERT_METHOD="both"
Cooldown protection
Cooldown files in /var/log/healthmonitor/.cooldown/ track last-sent timestamp per alert type. Duplicate alerts are suppressed for ALERT_COOLDOWN seconds (default: 1800).
ALERT_COOLDOWN=1800
